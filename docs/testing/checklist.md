# 测试清单

## 本机运行集成测试

集成测试需要本机可用的 Docker daemon。Docker Engine 28+ 将最低 API 版本提升到 1.44，
而 Testcontainers 内置 docker-java 在未显式配置时以 API 1.32 握手，报错
`client version 1.32 is too old. Minimum supported API version is 1.44`。
解决方法：在 `~/.docker-java.properties` 写入 `api.version=1.44`（Docker 25+ 均支持），
Testcontainers 检测到显式版本后不再回退到 1.32。

## 防超卖测试

测试环境使用**真实 PostgreSQL**（Testcontainers），而不是用 H2 或模拟 Repository 替代。

| 场景 | 验收标准 |
|--------|--------|
| 库存 1 张，100 个并发请求 | 最多一个请求成功预留 |
| 库存 10 张，100 个请求各买 1 张 | 总预留不超过 10 |
| 相同幂等键重复提交 | 不创建重复订单 |
| 订单事务中途失败 | 订单和库存预留整体回滚 |
| 两个 Worker 同时释放一个预留 | 库存只释放一次 |
| 同一独立票品并发购买 | 最多一个有效订单占用 |
| 订单取消与支付确认竞争 | 只有合法状态转换成功 |
| 支付结果未知 | 不会因为简单超时而错误释放库存 |

## 支付与恢复测试

必须覆盖：

- 重复支付回调。
- 金额与订单不一致。
- 支付渠道超时但实际扣款。
- 支付成功后应用崩溃。
- Outbox 消息重复消费。
- 退款回调重复到达。
- 部分退款累计金额校验。
- 支付成功但库存已被异常释放。
- 对账发现资金记录与订单状态不一致。

## 专场测试

- 至少两种模板能够渲染。
- 模块排序和配置变更有效。
- 非法模块类型无法发布。
- 恶意 HTML 或脚本不能执行。
- 草稿发布不会修改既有历史版本。
- 同一商品在不同专场展示时仍共用库存。
- 专场下线不影响已经创建的订单。
