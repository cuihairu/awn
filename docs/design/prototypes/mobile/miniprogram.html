与 Flutter 端差异
  • 原生能力：小程序无法自绘系统层，状态栏 / 返回 / 胶囊由微信托管；Flutter 端可自定义全部导航。
  • 支付：小程序仅能拉起微信支付（requestPayment 回调确认）；Flutter 端可并接支付宝等多渠道。
  • 分享：小程序天然支持卡片转发与朋友圈分享；Flutter 端需接入系统分享面板。
  • 包体限制：小程序主包 ≤ 2MB、整包 ≤ 20MB，座位图等重组件须放分包；Flutter 无此约束。
  • 性能降级：小程序画布能力弱，座位图仅 2D；Flutter 端预留 3D 线框升级路径。
小程序适配约束
  • 无 DOM：Taro 编译到小程序运行时，不能用浏览器 API 与直接 DOM 操作。
  • 分包加载：选座、订单详情等低频页放分包，控制首屏启动体积。
  • setData 性能：座位图状态更新须合并批量 setData，避免逐座刷新导致掉帧。
  • 支付回调：支付结果以后端回调为准，前端轮询补单，防丢单。
  • 地图组件授权：场馆地图使用小程序 map 组件需用户授权定位，未授权时降级为静态示意。
