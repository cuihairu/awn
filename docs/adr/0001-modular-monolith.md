# ADR-0001：采用 Spring Boot 模块化单体，暂不拆分微服务

- 状态：已接受
- 日期：2026-10-11

## 背景

AWN 是票务交易与情报平台，包含活动、商品、专场、订单、库存、支付、退款、履约、挂牌、情报等能力。团队规模小，第一阶段需要快速交付并保证交易正确性。

## 决策

采用 **Java + Spring Boot 单个 Maven 多模块工程**的模块化单体：

- 使用 [Spring Modulith](https://spring.io/projects/spring-modulith) 定义和验证逻辑模块、生成架构文档、执行模块级测试。
- 部署时只有一个 API 应用（`apps/awn-api`）和一个 Worker 进程（`apps/awn-worker`），Worker 运行相同代码包、只启用后台任务。
- 模块间只通过 `api` 包调用；Spring Modulith 结构测试在 CI 中强制执行边界。

## 后果

- 正面：事务边界简单（订单 + 库存 + Outbox 同库同事务）、部署运维成本低、重构成本低。
- 负面：单点部署，扩容受整体限制。
- 约束：禁止在没有架构决策（ADR）的情况下提前拆分微服务；等情报规模、部署独立性或实际负载确实要求拆分时再决定。
