## 采集红线

1. **不复制第三方仓数据文件**：参考公开结构，自行整理重建。
2. **版权不明不入库**：官方座位图（大麦/猫眼/场馆运营方）是版权作品，不复制其图片或矢量文件。
3. **容量与分区只用公开可查数值**：不编造精确座位号；样本不含 `sections` / `rows` / `seats` 字段。
4. **多口径并存**：容量数值冲突时两个口径都保留并注明差异，不静默择一（虹口 33,060 / 35,000）。
5. **未公开就是未公开**：`stands.count: null`、`notPublic` 清单如实登记，不用占位值冒充。

## 校验

```bash
node docs/data/venues/validate.mjs
```

- 4 份样本全部 PASS（结构校验 + 文件名与 id 一致 + 无座席级字段）。
- 同时输出**DB 覆盖度矩阵**：17 个样本字段中 14 个在当前 schema（venue V4/V19/V26 + platform_seats V17）无处落库——这是模型缺口证据，缺口断言失败说明 schema 已变，需更新矩阵。
- 校验脚本零第三方依赖，不引入 npm 包。

## 模型缺口与设计方案

现有 schema 表达不了场馆布局（类型 / 容量 / 看台 / 包厢 / 场地形状 / 面积 / 年份 / 双语名 / 缺口清单），且万体馆的双容量（随演出类型变化）单一容量字段表达不了。设计方案见 `docs/design/venue-layout-schema.md`。

## 数据可得性结论

公开渠道只能给到场馆级事实，**给不到分区 / 排 / 座级别**（4 个样本一致）。完整布局需场馆方 / 主办方的 CAD、SVG、PDF 或座位表。因此本批次不编造座席级数据，原型 `docs/design/prototypes/web/venue-layout.html` 中的排布为重建示意（虚线标注）。
