## 1. 令牌体系（tokenized，换主题不改布局）

### 1.1 语义颜色令牌（随主题变化，`--t-*`）

| 令牌 | 用途 |
|---|---|
| `--t-bg` | 页面背景 |
| `--t-sunken` | 下沉区域（座位图画布、代码块、内嵌面板） |
| `--t-card` | 卡片背景 |
| `--t-fg` / `--t-fg-muted` / `--t-fg-subtle` | 正文 / 次要 / 弱化文字 |
| `--t-brand` / `--t-brand-strong` / `--t-brand-soft` | 品牌色（主操作 / 强调 / 柔和背景） |
| `--t-on-brand` | 品牌色之上的文字 |
| `--t-hero-grad` | Hero 渐变背景 |
| `--t-border` / `--t-border-strong` | 边框 / 强边框 |
| `--t-success` / `--t-warning` / `--t-danger` / `--t-info` | 状态色 |
| `--t-shadow` | 阴影颜色（配合结构令牌 --shadow-1/2 使用） |
| `--t-accent-2` | 第二强调色（仅节日 / 季节主题定义） |
| `--tier-1` … `--tier-5` | 票档 1–5 色（座位图分区 / 票档圆点共用，两处不许各配一套） |

规则：组件 CSS 只允许引用令牌，**不允许出现裸 hex/rgb**（原型已按此执行并核验）。

### 1.2 结构令牌（不随主题变化）

| 组 | 令牌 |
|---|---|
| 间距 | `--space-xs/sm/md/lg/xl/2xl` |
| 圆角 | `--radius-sm/md/lg/pill` |
| 字体族 | `--font-body`（Noto Sans SC / PingFang SC）、`--font-display`、`--font-num`（数字等宽 tabular-nums，用于价格 / 坐标 / 排号） |
| 字号 | `--fs-xs/sm/md/lg/xl/2xl/hero` |
| 阴影 | `--shadow-1/2`、动效 `--dur-fast/base` |

### 1.3 主题机制

- 切换 = `<html data-theme="…">` 一个属性；`theme.js` 提供右上角悬浮切换器并记忆 localStorage。
- 布局、间距、字号、组件结构全部来自结构令牌 → 换主题不改布局（验收口径）。
- 「不许只换色就声称完成主题」：每套主题须给出色板 + 适用场景，并至少在一屏实际实例中验证（F1=dark、周杰伦=cn-mid-autumn、周传雄=season-autumn 已验证）。

## 4. 关键流程与状态

### 4.1 四态（空态 / 加载 / 错误 / 成功）

所有关键流程（列表、活动详情、座位图、下单、支付、admin 视图）都必须给出四态；原型在 `web/home.html`（列表四态）、`web/purchase.html`（下单/支付态）、`web/seatmap-2d.html`（L1 无排号态）已示范。

### 4.2 购买页全流程（web/purchase.html，优先专项）

选场次 → 票档/座位（选区/选排为主路径，逐座为可选）→ 数量与实名 → 下单 → 支付 → 出票。
必含状态：空态（无符合条件票档）、售罄（候补/换场次）、排队或抢购中、支付中（防重复提交）、支付失败（重试/换渠道）、超时关单（释放库存）、下单成功。
后端语义对齐：超时 ≠ 支付失败；渠道结果未知走对账（UNKNOWN 状态），前端不得把「未收到回调」直接当失败展示。

## 6. 场次数据模型（地理 + 座位）

### 6.1 地理位置字段（每场次，后台配置）

| 字段 | 说明 |
|---|---|
| `city` | 城市（定位缺失时列表按城市名排序降级） |
| `address` | 详细地址 |
| `lat` / `lng` | 坐标（展示于场次卡与详情） |

- 前端地图组件：**离线静态图 / 占位图为默认**（`map-box`），联网地图（高德/百度等 SDK）作为可选项接入，不做硬依赖。
- 列表能力：按距离排序（距离近优先），定位缺失降级城市名排序；城市 chips 筛选。

### 6.2 座位图数据模型（版本化；用户 2026-10-12 拍板的第一阶段范围）

第一阶段不是「逐座售票系统」，而是**可复用的场馆空间数据平台**：导入/维护场馆布局、展示看台与分区、表达演出舞台配置、把选区/选排结果关联到 AWN 商品与库存。优先覆盖中国大型体育馆/演唱会场馆，试点 20–50 个高频场馆。

```
Venue                    场馆身份：名称/地址/别名/城市/坐标/容量/来源
 └─ VenueLayoutVersion   基础布局版本：坐标系/原始资料引用/审核状态（可复用、带版本）
     └─ Section          分区：多边形边界/名称/编号/所在楼层
         └─ RowRange     排号规则：起止排/编号方向/适用分区 —— 仅在有可靠数据时维护，不虚构排号
 └─ EventSeatingConfiguration   演出配置（每场一版）：舞台方向/开放区域/封闭区域/临时座席/分区↔票档映射
     └─ AWN Product + InventoryPool   售卖：可售状态/库存/占座/订单/支付
```

边界红线：**座位图 = 空间与编号；库存 = 可售状态。两者不是一个模型。** 座位图里有某座位 ≠ 该演出开放销售；前端显示可选 ≠ 后台真有库存；选区/选排只是前端选择结果，提交后由 AWN 后端验证商品、库存与购买规则。

精度分级：

| 级别 | 内容 | 第一阶段 |
|---|---|---|
| L1 | 场馆轮廓/看台/分区（形状、名称、相对位置） | ✅ 必须（原型南/北看台即 L1，只展示分区不开放选排） |
| L2 | 分区/排号/座号与相对位置 | ✅ 目标（选区、选排；排号仅在有可靠数据时录入） |
| L3 | 逐座精确几何 + 座位状态与库存映射 | ⏳ 后续（逐座选择与占座才需要） |

数据采集：来源优先级 ①场馆官方公开平面图/座位图 ②主办方/票务方演出配置图 ③获许可公开数据 ④公开图片辅助人工建模；每份原始资料记录来源 URL/采集时间/授权状态/适用版本/审核结果；**每张图对应一份结构化布局，图片不单独作为数据**；半自动流水线 = 发现→导入原始→自动解析+人工校验（解析结果不得未经校验作为售票依据）→版本化发布。

### 6.3 座位图前端（2D 先行，3D 为 P2）

- **2D（P1，先做）**：`底图 + 可交互分区` —— SVG/Canvas 场馆轮廓，每个分区一个可点击多边形（填充=票档色），选中分区显示其可确认的排号范围（RowRange）；支持缩放/拖拽、售罄置灰、选中高亮；同一份座位数据（SECTIONS/RowRange 数据结构）驱动渲染。
- **2D/3D 切换**：按钮位于座位图区右上；两套视图共享同一数据模型与选座状态，切换不丢选中。
- **3D（P2，等 2D 过目后再做原型）**：同一份数据换渲染器（three.js/WebGL），程序化几何生成座位（不引外部建模素材），视角旋转/俯仰、「跳到某区」。
- **3D 风险与成本（如实）**：①渲染——上万座位需 InstancedMesh 批渲染，低端 GPU 帧率不稳；②拾取——Raycaster 命中 instanceId，缩放很小时点选精度差，需放大阈值或回退到排/区选择；③移动端降级——低端机/帧率不达标自动回 2D，降级阈值需实测；④成本——3D 渲染器为独立实现（Flutter 侧另做），工作量约等于 2D 的 1.5–2 倍。
- **帧率目标（验收口径）**：桌面 ≥ 60fps，移动 ≥ 30fps，验收时实测并记录；L1/L2 展示默认 2D，3D 仅对逐座选择场景开启。

### 6.4 座位图数据来源与立项（先验证后立项）

调研结论见 `docs/research/venue-seatmaps.md`（19 个条目，逐项含许可/数据格式/中国场馆覆盖/复用性/活跃度/出处）。要点：没有单一开源项目同时覆盖数据+2D+3D+Flutter；中国场馆座位级开源数据为零；GPL-3.0（SeatMap-JS）与 AGPL-3.0（pretix）因传染性排除；MIT 参考对象为 seatmap-canvas（2D 交互）与 Fi-Stadium（three.js 程序化 3D 路线验证）。

**用户拍板（2026-10-12）：先不立项 `venue-seats`**，先做三问验证：①能否找到 5 个目标场馆可用、来源明确的基础座位图；②能否整理成统一分区数据并在 AWN 前端正确展示；③同一场馆两场不同演出能否复用基础布局、只改舞台与开放区域配置。成立后再决定抽独立项目。

### 6.5 场次后台配置字段清单（admin/session-config.html）

| 组 | 字段 |
|---|---|
| 基本信息 | `sessionName` / `startAt` / `doorsAt` / `status` |
| 地理位置 | `city` / `address` / `lat` / `lng`（+ 地图预览，离线静态图） |
| 座位/分区 | `layoutVersion`（引用 VenueLayoutVersion）/ `sections[]`（名称/编号/楼层/票档映射/是否开放）/ `rowRanges[]`（起止排/方向，仅录入有可靠数据的）/ 舞台方向 / 开放与封闭区域 |
| 票档映射 | `tiers[]`：Section(或 Section+RowRange) ↔ Product ↔ InventoryPool |
| 活动页 | 见 §5 字段清单 |

## 7. 实现纪律（原型过目后执行）

1. 对照原型逐屏实现，每屏报「已对上 / 有差异 / 未实现」三档 + 截图证据。
2. 公共组件抽公共件（§3 复用关系为抽取清单）。
3. 换主题不改布局（验收：同一屏切 11 套主题布局零位移）。
4. 不许只换色就声称完成主题。
5. 3D 原型等 2D 过目后再做；实现等原型过目后再动。
