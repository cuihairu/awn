# Source Layer Split Rationale

English | [中文](../zh/architecture/source-layer-split-rationale.md) · [Architecture](source-layer-architecture.md) · [Glossary](source-layer-glossary.md)

These reasons are numbered for traceability. Each rule points to source behavior observed at commit `7e43d70`.

1. **Client channels and reusable presentation are separate because they consume one HTTP contract while owning different transports and screen lifecycles.** Web depends on the shared API client, campaign renderer, ticket components, and UI package (`apps/web/package.json:10-15`); the miniprogram uses its own Taro transport (`apps/miniprogram/src/lib/taro-transport.ts:10-37`) and page routes (`apps/miniprogram/src/app.config.ts:1-32`); Flutter owns Dio and native model classes (`apps/client/lib/src/api/awn_client.dart:4-40`). Collapsing them would couple browser lifecycle to Taro/Dio transport.
2. **Composition root is separate because HTTP policy is not business logic.** API startup exists only for HTTP (`apps/awn-api/src/main/java/site/awn/AwnApplication.java:6-17`); trace propagation, API authentication, and admin rate limiting are servlet filters (`apps/awn-api/src/main/java/site/awn/api/TraceIdFilter.java:14-55`; `apps/awn-api/src/main/java/site/awn/api/auth/ApiAuthenticationFilter.java:15-77`; `apps/awn-api/src/main/java/site/awn/api/AdminAuthFilter.java:29-96`), while the exception adapter translates deliberately exposed domain exceptions into HTTP semantics (`modules/awn-order/src/main/java/site/awn/order/domain/package-info.java:1-6`; `apps/awn-api/src/main/java/site/awn/api/ApiExceptionHandler.java:16-101`).
3. **Business modules are separate because dependencies and public contracts are explicitly directed.** The Maven module list names the business modules (`pom.xml:26-46`), and POMs record actual cross-module edges such as catalog→event, inventory→catalog, marketplace→audit, order→inventory/marketplace/catalog, and payment→order (`modules/awn-catalog/pom.xml`; `modules/awn-inventory/pom.xml`; `modules/awn-marketplace/pom.xml`; `modules/awn-order/pom.xml`; `modules/awn-payment/pom.xml`). Package Javadoc allows only named API interfaces and explicitly exposed domain exceptions (`modules/awn-order/src/main/java/site/awn/order/api/package-info.java:1-6`; `modules/awn-order/src/main/java/site/awn/order/domain/package-info.java:1-6`).
4. **A module keeps application, domain, and persistence concerns apart because stable invariants and replaceable adapters change at different rates.** Order creation is an application-service transaction (`modules/awn-order/src/main/java/site/awn/order/application/OrderWriteService.java:88-198`) above an order state machine (`modules/awn-order/src/main/java/site/awn/order/domain/Order.java:14-132`) and JPA repositories (`modules/awn-order/src/main/java/site/awn/order/infrastructure/OrderRepository.java:13-44`). Payment creation follows the same boundary (`modules/awn-payment/src/main/java/site/awn/payment/application/PaymentFacadeImpl.java:88-130`).
5. **Shared backend infrastructure is separate because persistence units and reliable messaging cross all business modules.** The trading and intelligence repository scanners and entity managers are configured together in `awn-shared` (`modules/awn-shared/src/main/java/site/awn/shared/config/PersistenceConfig.java:43-96`), while outbox claiming, inbox deduplication, retry, lease, and failure alerting form one reusable protocol (`modules/awn-shared/src/main/java/site/awn/shared/outbox/OutboxMessage.java:14-86`; `modules/awn-shared/src/main/java/site/awn/shared/outbox/OutboxDispatchService.java:17-131`; `modules/awn-shared/src/main/java/site/awn/shared/inbox/InboxMessage.java:14-55`).
6. **API and Worker are separate runtime layers because HTTP and scheduled side effects have opposite safety envelopes.** API explicitly disables Worker execution (`apps/awn-api/src/main/resources/application.yml:55-58`), Worker disables the business web server and enables scheduling (`apps/awn-worker/src/main/java/site/awn/worker/AwnWorkerApplication.java:6-27`), and each task independently checks global/task switches (`apps/awn-worker/src/main/java/site/awn/worker/task/OrderTimeoutTask.java:27-39`; `apps/awn-worker/src/main/resources/application.yml:43-61`).
7. **Data is a separate layer because PostgreSQL authority and Redis choice have distinct guarantees.** Two persistence units keep `site.awn.intelligence` repositories and transactions apart from trading (`modules/awn-shared/src/main/java/site/awn/shared/config/PersistenceConfig.java:43-96`); migration ownership prevents concurrent migration (`apps/awn-api/src/main/resources/application.yml:22-31`; `apps/awn-worker/src/main/resources/application.yml:22-24`); Redis versus memory is a conditional limiter implementation with different multi-instance guarantees (`modules/awn-shared/src/main/java/site/awn/shared/ratelimit/RedisRateLimiter.java:10-33`; `modules/awn-shared/src/main/java/site/awn/shared/ratelimit/InMemoryRateLimiter.java:10-17,35`).
8. **Deployment is separate because process images, proxy routing, backing stores, credentials, and health ordering are operational concerns.** API and Worker have distinct multi-stage Dockerfiles and exposed ports (`deploy/docker/api.Dockerfile:5-41`; `deploy/docker/worker.Dockerfile:1-41`); Caddy path-routes three frontends (`deploy/config/caddy/Caddyfile:4-20`); Compose assigns trading/intelligence/migration roles and waits for API health before Worker (`deploy/docker-compose.yml:52-73,96-106`).
